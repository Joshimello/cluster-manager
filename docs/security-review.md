# V1 security review

Reviewed for the first deployment on 2026-09-16. This is a focused review of the v1
trust boundaries, not a third-party penetration test.

| Area                         | Control and review result                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Remaining operator responsibility                                                                                                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web authentication           | Argon2id password verifiers, random hashed server sessions, HTTP-only/SameSite cookies, forced temporary-password change, session revocation on reset/disable. Cookies are `Secure` for HTTPS; explicitly allowed private-overlay HTTP uses non-`Secure` cookies so browsers can authenticate. Runtime CSRF checks trust the canonical origin plus only exact origins listed in `CSRF_TRUSTED_ORIGINS`; wildcards are rejected. Last-admin safeguards are enforced.         | Prefer HTTPS. Keep `CSRF_TRUSTED_ORIGINS` minimal. If `ALLOW_HTTP=true`, restrict network access, administrator accounts, and backups.                                                                     |
| Authorization                | Server-side user/admin guards cover pages and actions. Node APIs use separate workstation credentials and bind records/instructions to that workstation.                                                                                                                                                                                                                                                                                                                    | Review audit events and promptly disable departed users.                                                                                                                                                   |
| Credential exposure          | Temporary, enrollment, and recovery credentials are shown once. Node secrets are stored hashed centrally and mode 0600 locally. Logs omit passwords, hashes, tokens, arguments, and environments.                                                                                                                                                                                                                                                                           | Deliver one-time secrets out of band; keep `.env`, node state, and terminal scrollback private.                                                                                                            |
| Desired-state reconciliation | Versioned, authenticated, workstation-scoped state; mandatory platform UID/GID validation; root-only creation journal/provenance; exact private-group creation; idempotent changes; username, UID, GID, and managed-identity collisions fail before SSH/account mutation; revocation locks only that node while preserving homes and running work.                                                                                                                          | Reserve `20000–59999` everywhere. Never adopt or renumber a pre-existing identity; deliberately resolve collisions or purge/recreate provenance-owned development accounts.                                |
| Shared NFS identity          | A never-reused equal UID/GID is applied on every assigned node, making ordinary numeric ownership consistent. Homes and NFS configuration remain local/operator-managed.                                                                                                                                                                                                                                                                                                    | Use `root_squash`, restrict exports to managed networks, and recognize that `AUTH_SYS` cannot defend against a privileged malicious client impersonating a UID.                                            |
| Node privilege               | Root is required for `/proc`, account/password/SSH management, and signals. systemd isolates temporary/kernel/namespace surfaces while deliberately leaving host account files, homes, devices, and processes visible. No arbitrary-command API exists.                                                                                                                                                                                                                     | Limit root access and install only signed/trusted binaries and configs.                                                                                                                                    |
| Platform image supply chain  | GitHub Actions tests the platform and publishes release-tagged multi-architecture images to GHCR. Production Compose pulls the selected tag instead of building unreviewed source on the host.                                                                                                                                                                                                                                                                              | Prefer an immutable release tag, review the linked workflow/release, and record the pulled digest for high-assurance deployments.                                                                          |
| Node update control          | Only capable, authenticated nodes can claim workstation-scoped instructions. Admin updates require an exact newer stable tag and workstation-name confirmation. The node verifies the release SHA-256 and candidate version, atomically saves the prior binary/unit, and arms a local rollback watchdog before replacement. Success requires three consecutive authenticated heartbeats; config, credentials, accounts, homes, and jobs are outside the update transaction. | Use canary rollouts and review release provenance. GitHub HTTPS plus published SHA-256 checksums detects corruption but is not artifact signing; stronger signature verification remains future hardening. |
| GPU diagnostic control       | Admin-only instructions contain bounded typed parameters, never commands. Platform and node both require idle targets; reservations and updates are excluded. The node accepts only a checksummed release-manifest digest, uses Podman/CDI without network, enforces local duration and thermal limits, and recovers only its exact recorded transient unit. Logs are sanitized and bounded. | Stress testing can expose latent hardware faults and is not proof of health. Use short tests, observe cooling and power capacity, and investigate thermal stops or faults before returning a node to users. |
| Telemetry/privacy            | Host and GPU resource history contains utilization, temperature, and capacity values only. Process telemetry is limited to executable name, PID identity, UID/username, and GPU memory. User views filter other users' process detail and reservation identity. High-frequency rows have bounded retention.                                                                                                                                                                | Choose the shortest useful retention and control database access.                                                                                                                                          |
| Reservations                 | PostgreSQL exclusion constraint prevents overlap under concurrency; admin overrides require explicit reasons and do not bypass overlap. History is retained.                                                                                                                                                                                                                                                                                                                | Reservations coordinate use but do not enforce device access.                                                                                                                                              |
| Process termination          | User requests require their live conflicting reservation. Admin-only, narrowly scoped instructions expire quickly and are claimed once. Node revalidates workstation, PID, UID, and start ticks before SIGTERM and any explicit SIGKILL escalation.                                                                                                                                                                                                                         | Review captured/current identity and reason before acting; automatic expiry termination is intentionally absent.                                                                                           |
| Availability/recovery        | Readiness probes include PostgreSQL, services restart, nodes back off, state reconciliation is idempotent, and backup restoration is rehearsed. Control-plane loss does not terminate SSH/workloads.                                                                                                                                                                                                                                                                        | Maintain off-host backups, monitor capacity, and rehearse recovery after upgrades.                                                                                                                         |

Accepted v1 limitations: local password authentication is used for managed accounts;
there is no MFA, external identity provider, LDAP/FreeIPA, Kerberos, shared group/ACL
management, shared homes, job isolation, GPU device enforcement, or separate
observability stack. These are explicit scope choices. Expose the platform
only to the intended institutional network/VPN and revisit the threat model before
internet exposure, multi-tenant use, or adding remote-control capabilities.
